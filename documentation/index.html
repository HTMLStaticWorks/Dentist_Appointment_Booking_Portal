Aura Dental Booking Portal Architecture

A complete overview of the design tokens, components, file architecture, strict color system, and patient booking dataflow.

1. Color Palette System

Role Name Hex Code Usage
Primary Deep Navy Blue #12304A Headings, Primary Buttons, Navigation, Footer, Badges
Secondary Clean White / Soft Neutrals #FFFFFF / #F8FAFC Card backgrounds, crisp borders, contrast text
Accent Professional Teal #19A7A0 Icons, Focus rings, CTAs, Highlights, Badges

2. Section Count & Layout Architecture

  • • index.html (Home 1): Exactly 6 sections (Hero, Clinic Intro & Stats, 6 Dental Services, 4 Dentists, 3 Testimonials, Appointment CTA).
  • • pages/home-2.html (Home 2): Exactly 6 sections (Editorial Split Hero with Subtext, 4 Benefits, 4-Step Treatment Journey, Cosmetic Dentistry Feature, Clinic Experience Showcase, Final CTA).
  • • All Other Pages: Exactly 4 sections each (Hero, Core Content Grid/Details, Standards/Approach, Action CTA).
  • • Patient Portal (pages/dashboard.html): Interactive responsive client-side app managing appointments, treatment history timeline, reminders, profile, and settings.

3. Interactive LocalStorage Sync

When a patient schedules a visit via pages/booking.html, the appointment payload is stored in localStorage.aura_appointments. The pages/dashboard.html reads this in real time, updating the Overview tab metrics, active upcoming bookings, and reschedule/cancellation modals.

4. Accessibility & Standards

Compliant with WCAG 2.1 AA contrast requirements across both Light Mode and Dark Mode. Fully keyboard navigatable with visible focus states, ARIA landmarks, mobile-first responsive breakpoints (320px–1920px), and RTL support.
